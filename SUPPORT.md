# Support

## Where to ask

| You want to… | Go to |
|---------------|-------|
| Report a bug | [New issue → Bug report](https://github.com/hamanakam1/el-hidratador/issues/new/choose) |
| Request a feature | [New issue → Feature request](https://github.com/hamanakam1/el-hidratador/issues/new/choose) |
| Ask a question | [New issue → Question](https://github.com/hamanakam1/el-hidratador/issues/new/choose) |
| Improve the docs | [New issue → Documentation improvement](https://github.com/hamanakam1/el-hidratador/issues/new/choose) |
| Discuss an idea or a design | [Discussions](https://github.com/hamanakam1/el-hidratador/discussions) |
| Read or extend the wiki | [Wiki](https://github.com/hamanakam1/el-hidratador/wiki) |
| Report a vulnerability | [Private security advisory](https://github.com/hamanakam1/el-hidratador/security/advisories/new) — **not** a public issue |

Before opening an issue, check the [open issues](https://github.com/hamanakam1/el-hidratador/issues)
and [Discussions](https://github.com/hamanakam1/el-hidratador/discussions); the
`roadmap` label marks work that is already planned.

## What to include

A good report contains:

- the exact command you ran
- the exact JSON you got back (it is the whole output, and it is machine readable)
- the version: `hidratador --version`
- the environment: operating system, Python version, install method
- what you expected instead

Do not include credentials, tokens, private transcripts, internal hostnames, or
real ticket data. Use synthetic identifiers such as `M-1001` and `repo/api`.

## Response

- Bug reports are triaged with the `triage` label and the `needs-triage` state.
- Questions are usually answered in Discussions rather than in an issue.
- Security reports follow [SECURITY.md](SECURITY.md) and are not discussed in
  public until a maintainer agrees a disclosure timeline.
